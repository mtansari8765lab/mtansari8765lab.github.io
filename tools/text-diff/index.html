About this text diff checker

A text diff checker compares two versions of a text and shows exactly what changed between them. Paste the original into one box and the revised version into the other, and the tool highlights every difference word by word: words that were added appear in green, words that were removed appear in red with a strikethrough, and everything that stayed the same is left plain. Instead of reading two drafts side by side and hunting for edits by eye — a slow job where small changes slip past unnoticed — you get the full list of changes in one glance.

Writers and editors use it to check what changed in a revised draft. Contract reviewers compare a returned redline against the agreed version to confirm nothing extra slipped in. Students compare essay drafts to see what a tutor or classmate edited. Developers and support staff compare two versions of a config file, an error log, or a customer message to find the one line that changed. Translators check a revised translation against the first pass for dropped paragraphs. Anywhere two versions of the same text exist and the differences matter, a diff is faster and more reliable than reading both from scratch.

The comparison runs entirely in your browser with JavaScript — your text is never uploaded, stored, or sent anywhere, so contracts and unpublished drafts stay private. The tool splits both texts into words and finds the longest common subsequence: the longest run of words both versions share in the same order. Everything else is a change. Because the comparison is word-level rather than line-level, editing one word inside a sentence highlights just that word instead of flagging the whole sentence — which is what makes the results readable for prose. Line breaks and spacing are preserved in the output, so the diff reads like the original document.

Worked example

Take a nine-word sentence and change two words in it. Original: "The quick brown fox jumps over the lazy dog." Modified: "The quick red fox leaps over the lazy dog." The diff highlights brown and jumps in red (removed) and red and leaps in green (added); the other seven words stay plain. The stats panel reads: 9 words in the original, 9 in the modified version, 2 words added, 2 words removed, 7 unchanged — exactly what the tool reports, so you can check the counts before trusting a diff on a longer document.

How to use

  1. Paste the original text into the first box and the modified text into the second.
  2. Click Compare — the diff appears below with additions in green and deletions in red.
  3. Check the stats panel for the word counts and the number of words added, removed, and unchanged.
  4. Use Copy result to copy the diff as text, Swap to reverse the two inputs, or Sample to try the tool with example texts.

Limitations

  • The comparison is exact-match and case-sensitive: "Hello" and "hello" count as different words, so normalize case with the case converter first if case doesn't matter.
  • Moved text shows as a deletion plus an addition — the tool finds the smallest set of edits, not "this paragraph moved".
  • Formatting noise (different line endings, trailing spaces) can make whole passages look changed; run both texts through the text cleaner first if a diff looks suspiciously large.
  • Very long documents (tens of thousands of words) may take a few seconds to compare.

Frequently asked questions

How does the text diff tool work?

It splits both texts into words and finds the longest common subsequence — the longest run of words both versions share in the same order. Words outside that shared run are reported as added (in the modified text only) or removed (in the original only). The comparison uses Hirschberg's algorithm, which finds the same minimal edit set as a full dynamic-programming diff but with far less memory.

Is my text uploaded anywhere?

No. The diff runs 100% in your browser with JavaScript. Your text never leaves your device.

What is the difference between a word-level and a line-level diff?

A word-level diff compares word by word, so changing one word inside a sentence highlights just that word. A line-level diff compares line by line, so the same edit flags the entire line as changed. Word-level is better for prose; line-level is better for code and config files.

Why does my diff show the whole document as changed?

Almost always formatting noise: different line endings, trailing spaces, or re-wrapped paragraphs. Run both texts through the text cleaner first to normalize them, then diff again — the real changes will stand out.
